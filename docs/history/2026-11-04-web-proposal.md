# A web front end for the Agent Rush demo

**Decision requested · November 4.** Approve a single-owner page on the same disposable Vultr VM as the browser engine, or defer the web app. Estimated implementation and offline verification: one developer day. Allow another half day on a provisioned VM for TLS, containment checks and a recorded run. The existing [terminal runner](../../tools/HireZero.Engine.Run/Program.cs) provides the reference flow.

**Owner view.** One ASP.NET minimal API project, `src/HireZero.Engine.Web`, serves a static form. The owner enters a goal and one public HTTPS origin. Draft displays the normalized origin, steps, limits and full digest. Approve posts the job ID and digest. The host reloads the immutable saved packet and compares its digest before dispatch. The result view shows captured text, bounded JPEGs, the answer, token use, broker events and teardown. Reuse [BrowserTask](../../src/HireZero.Agent/BrowserTask.cs), the qualification check and the existing broker. The model credential and Docker socket stay on the host.

**Who can do what.** Protect draft, approval and private results with one owner login or a rate-limited passphrase and a short-lived HTTPS-only session. Draft itself spends tokens. Judges can open a public read-only gallery of owner-selected, redacted snapshots. Publish explicitly to that gallery, separate from private run folders. Reading a snapshot cannot draft, approve or replay a job.

**Execution boundary.** Accept one draft or run at a time in one worker process with one usage ledger. Enforce run and monthly caps, cap request bodies and rate-limit paid endpoints. Protect state-changing requests against CSRF. Store packets by server-generated ID, bind approval to the owner session and atomically consume it before dispatch. After interruption, expose the saved evidence and unresolved teardown state for operator review. Replay requires a new packet. Treat page text and model answers as untrusted text. Serve only allowlisted screenshot and summary files by ID.

**Hosting and added exposure.** Terminate HTTPS at a reverse proxy on TCP 443 and bind the app to loopback. Provision the certificate before the demo, with DNS validation if port 80 stays closed. The [current bootstrap](../../deploy/vultr/bootstrap.sh) opens SSH only when UFW is present. Deployment needs a reviewed 443 rule at both host and provider firewalls, and a check from outside the VM. The public listener, sessions, file-serving routes and cost-bearing draft route are new attack surfaces. Keep the public gallery handler away from the Docker socket and inference key. A private owner-side worker owns execution and teardown.

**Acceptance.** With fakes, show that anonymous visitors can read only selected summaries, draft/approve require an owner and CSRF protection, and stale or double approvals never execute twice. On Vultr, demonstrate HTTPS, a qualified browser run, a receipt and an empty post-run container list. Record the chosen architecture in a new ADR before implementation.
